03 / MAINTENANCE

업데이트와 복구

기존 설정을 보존하며 새 버전을 적용하고, 필요할 때 이전 설치 상태로 돌아가세요.

현재 버전과 업데이트 확인안전하게 적용하기이전 설치 상태로 복구패키지 검증과 한계적용 후 확인

현재 버전과 업데이트 확인

업데이트는 공식 저장소의 공개된 안정 릴리스를 사용합니다. 개발 브랜치나 시험 버전을 자동 설치하지 않습니다.

버전 확인
watchsmith version
watchsmith update --check

--check는 설치된 버전·사용 가능한 버전과 릴리스 안내를 확인하며 로컬 설치 파일을 바꾸지 않습니다. 실제 패키지 내용 검증은 업데이트를 적용할 때 수행됩니다.

안전하게 적용하기

  1. Codex 작업과 관련 watchdog 실행을 마칩니다.
  2. 설치 변경의 영향을 받는 클라이언트를 닫습니다.
  3. 아래 명령으로 업데이트를 적용합니다.
  4. Codex와 터미널을 다시 열고 설치 상태와 휴대폰 알림을 확인합니다.
업데이트 적용
watchsmith update --quiesced
--quiesced는 중지를 확인하는 표시입니다.

명령이 다른 작업이나 앱을 자동 종료하지 않습니다. 적용 전에 사용자가 영향을 받는 작업을 마쳐야 합니다.

업데이터는 실행 중인 자신의 설치 위치를 따릅니다. 다른 셸의 CODEX_HOME 값만 바꿔 별도 설치 위치로 돌리지 않습니다. 다운로드·검증 실패 시 설치 파일을 변경하지 않고, 설치 중 실패는 복구 기록을 사용합니다.

이전 설치 상태로 복구

업데이트 후 문제가 생겼다면 관련 작업을 멈추고 클라이언트를 닫은 뒤, 가장 최근 설치 변경을 되돌릴 수 있습니다.

최근 설치 복구
watchsmith rollback --quiesced

복구는 로컬 기록을 사용하므로 네트워크나 Git이 필요하지 않습니다. “최근 설치 변경”은 버전 업데이트뿐 아니라 수동 설치일 수도 있습니다. 특정 기록을 복구할 때만 해당 기록의 정확한 ID를 지정하세요.

특정 기록 복구
watchsmith rollback --transaction TRANSACTION_ID --quiesced

TRANSACTION_ID는 실제 복구 대상 ID로 바꿔야 합니다. 이후 사용자가 수정한 내용과 충돌하면 그대로 덮어쓰지 않습니다. 파일별 복구이므로 모든 파일이 동시에 전환되는 것은 아니며 이미 발송된 알림도 회수하지 못합니다.

패키지 검증과 한계

적용 전에 패키지 체크섬, 버전, 파일 목록, 개별 파일 해시를 확인합니다. 안전하지 않은 경로나 불완전한 패키지는 설치 프로그램 실행 전에 거부됩니다.

체크섬은 손상이나 자산 불일치를 검사하는 값이며 발행자 서명은 아닙니다. 신뢰의 기준은 HTTPS와 공식 GitHub 저장소·릴리스 계정입니다. 업데이트는 백그라운드에서 자동 실행되지 않습니다.

v0.1.0처럼 필요한 업데이트 자산이 없는 설치는 수동 이전이 필요합니다. 현재 설치를 지우기보다 기존 설정과 백업을 보존한 채 공식 릴리스의 설치 안내를 확인하세요.

적용 후 확인

업데이트 후 진단
watchsmith version
watchsmith doctor

버전과 설치 상태를 확인하고 작은 작업으로 실제 휴대폰 알림을 확인하세요. 진단 통과만으로 기기 수신이나 MCP 인증이 검증되지는 않습니다.
