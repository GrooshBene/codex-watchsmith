서로 다른 신호를 구분해 연결합니다.

MCP

의미 있는 진행 알림

에이전트가 설치된 지침에 따라 실제 작업 단계에 맞춰 Live Activity를 시작하고 업데이트합니다.

Watchdog

오래 걸리는 CLI 실행 보완

래퍼로 실행한 단발성 CLI 작업에서 기본 60초가 지나도록 에이전트의 진행 알림이 없으면 외부 감시기가 보완합니다. CLI 지원에 따라 Live Activity 또는 Push를 사용합니다.

사용 환경 준비

ActivitySmith 계정과 iOS 앱을 연결하고 알림을 허용하세요. Mac에는 zsh·Python 3.11 이상과 로그인한 Codex가 필요합니다. CLI 설치에는 Node.js/npm을 사용합니다.

압축을 풀고 설치

진행 중인 작업을 마친 뒤, 다운로드한 릴리스의 압축을 푼 폴더에서 실행하세요. 설정 마법사가 환경 확인과 API 키 등록을 안내합니다.

./setup.sh

명령만 복사합니다. 웹페이지에서 실행하지 않습니다.

연결 확인과 휴대폰 테스트

ActivitySmith MCP를 연결하고 Codex와 터미널을 다시 여세요. watchsmith doctor로 설치를 점검하세요. 마지막으로 실제 휴대폰에 테스트 알림이 보이는지 확인합니다.

기존 설정을 존중하고,
보낼 내용을 선택합니다.

기존 알림 연결과 설정은 보존하고, API 키는 macOS Keychain에 저장합니다.

완료 미리보기는 요청·응답에서 선택한 텍스트를 ActivitySmith로 전송합니다. 내용 없는 일반 알림으로 설정할 수 있으며, 상세 메타데이터 공유에는 별도 동의가 필요합니다.

자주 묻는 질문

응답 종료 알림은 작업 성공을 의미하나요?

아닙니다. 응답 종료는 에이전트의 이번 응답이 끝났다는 뜻입니다. 작업 성공 여부는 실제 검증 결과와 남은 문제를 함께 확인해야 합니다. 서버가 알림 전송을 수락했다는 사실도 휴대폰 화면에 표시됐다는 증거는 아닙니다. 응답 종료와 작업 성공 알아보기 →

진행 알림과 완료 알림을 모두 연결해야 하나요?

진행 상황은 ActivitySmith MCP로, 완료 Push와 CLI 감시는 API 키로 연결합니다. 두 인증은 별개입니다. MCP 없이도 완료 Push와 CLI 감시는 사용할 수 있습니다. 연결 방식과 설정 순서 →

알림에 작업 내용을 표시하지 않을 수도 있나요?

가능합니다. 완료 알림을 보내는 실행 환경에 WATCHSMITH_COMPLETION_PREVIEW=0을 설정하면 내용 없는 일반 알림을 보냅니다. 공유 범위와 설정 방법 →

기존 설치를 업데이트하려면 어떻게 하나요?

watchsmith update --check로 먼저 확인하세요. 진행 중인 작업을 마치고 영향을 받는 클라이언트를 닫은 뒤 업데이트합니다. 업데이트·복구 안내 →
